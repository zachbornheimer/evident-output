# Migrating to 1.1

Every breaking change from the 1.0.x line, with the exact before/after code.
If a call site does not appear below, it did not change. 1.1 is a deliberate
breaking release like 1.0 was (no compat shims) — see the repository's
release policy in AGENTS.md.

## `TaskHandle.Warn` now takes `ProblemOption`s and returns `*TaskHandle`

**Before (1.0):**

```go
func (t *TaskHandle) Warn(summary string)
```

**After (1.1):**

```go
func (t *TaskHandle) Warn(summary string, opts ...ProblemOption) *TaskHandle
```

Every existing `task.Warn("summary")` call site still compiles unchanged —
`opts` is variadic and the return value was never required to be used. What
changed is that a warning can now carry the same structured metadata a
`Problem`/`Fail`/`Block` can (`evo.Detail(...)`, `evo.Code(...)`,
`evo.On(...)`, `evo.Location(...)`, `evo.Next(...)`):

```go
task.Warn("stale entry ignored",
    evo.Detail("cache/entry-42.json is 9 days old"),
    evo.Code("CACHE-001"),
    evo.Location("cache/entry-42.json", 0, 0),
)
```

`Warn` still does not resolve the task (ZYS-848 keeps 13-problem doc P2:
"warnings annotate lifecycle; they do not replace it") — the return value
exists only so a call site may chain a following `*TaskHandle` method, the
same shape `Next`/`NextCommand` already had.

## `TaskHandle.Problem` — a Task can now own many blocking findings

New in 1.1, not a rename: `TaskHandle.Problem(summary string, opts
...ProblemOption) *TaskHandle` appends one blocking Problem to the task
without resolving it — call it as many times as the task has findings
instead of creating one `Task` per finding or flattening every finding into
one `errors.New(strings.Join(...))` string:

```go
task := out.Task("file integrity")
for _, issue := range issues {
    task.Problem(issue.Summary,
        evo.On(issue.Path),
        evo.Code(issue.Code),
        evo.Location(issue.Path, issue.Line, 0),
    )
}
task.Define(func(context.Context) error { return nil })
```

If `Define`'s callback returns `nil` (or a bare `task.Done()` is called)
while the task has accumulated Problems, the task resolves **Failed**, not
Done — accumulated blocking evidence overrides a claimed clean outcome. The
task still resolves exactly once; Problems never become child Tasks. Every
accumulated Problem survives in `Snapshot`/JSON/JSONL even though the plain
human view bounds how many render inline (`maxVisibleProblems`, same bound
`Fail`/`Block` already used for a Detail's evidence lines) — the omitted
count still renders as `"and N more failures"` and the count itself is
always authoritative.
