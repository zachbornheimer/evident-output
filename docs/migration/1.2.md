# Migrating to 1.2

1.2 adds no exported API and removes none. A 1.1 host needs no code
change, and its lifecycle, exit codes, `run_id`, errors, and wire bytes
are the same as in 1.1 on every format. Decision record:
[`docs/decisions/caller-cancellation.md`](../decisions/caller-cancellation.md).

## What stays exactly as in 1.1

- **Signals.** evo acts on SIGINT/SIGTERM only while the run callback
  runs. A signal that arrives after it returned is caught and ignored, so
  the Define work Finish waits on completes. This holds on every format:
  human, `FormatData`, `FormatJSON`, `FormatJSONL`, and `FormatExternal`.
- **The caller's `ctx`.** It reaches Tasks unchanged. When it ends mid-run,
  the running Define fails its row and the run concludes `failed` (exit 2).
- **Run identity.** `run_id`, `Conclusion.RunID`, and `Snapshot().OutputID`
  are `out_1`, and the first Task is still `task_2`.
- **Errors.** A `WriteJSON` write failure returns the writer's own error,
  unchanged (`err == syscall.EPIPE` still works). A `FormatJSON` write
  failure from `Finish`/`Close` is still one wrap of `ErrRenderer` with
  the writer error's text (`evo: renderer failure: <writer error>`).
- **Wire documents.** A run stopped by SIGINT/SIGTERM writes the 1.1
  `"evo.run"` document and JSONL `run.finished` payload, with no new key.
  The cause stays in `Conclusion.Explanation` (`by user`), and
  `schema/run.v2.json` is unchanged.

## Fixed

- **A run waiting on the state lock stops on ^C.** A run whose Define is
  queued behind another run's exclusive manifest lock (spec §11.3), while
  the run callback is still running, now stops on ^C with exit 130, as
  the 1.1 contract promised. Before, the wait held the Output's lock, so
  the ^C hung until the other run finished.

## Added

- **`WriteJSON` and `FormatJSON` share one writer,** so their documents
  stay byte-identical for the same run. Both already were in 1.1.
- **MCP API-063.** Review reports package-level `evo.Task`/`Group`/
  `Sequence`/`Fact`/`Warn`/`Print*`/`Confirm` reached from an Isolated
  Output's `Run` callback, including inside the package functions it
  calls. It fires for the current recommendation and for pins at 1.2.0 or
  later, never for a 1.0.x or 1.1.x pin.
- **HTTP embedding guide and example.**
  [`docs/guides/http-embedding.md`](../guides/http-embedding.md) and
  `examples/launch-agent-http` show one model serving the CLI and an HTTP
  endpoint on the 1.1 API.

## Deferred: a host-owned lifecycle (ZYS-947)

A mode where the request `ctx` is the run's lifecycle (its end concludes
`cancelled`, 130, and evo leaves process signals to the host) and a
per-run `run_id` both need new exported `Config` fields. A
machine-readable cancellation cause on the wire (DEC-CANCEL-007) waits
with them: while a signal is the only thing that can cancel a run,
`"outcome": "cancelled"` already says everything the cause would. ZYS-946 requires
one real embedder before the public surface grows, so both wait for the
next real consumer (ZYS-947). Until then, an HTTP host checks its own
`ctx.Err()` to tell a request that ended from work that failed, and
correlates on its own request id.
