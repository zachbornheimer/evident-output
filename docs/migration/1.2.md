# Migrating to 1.2

1.2 removes no public API. It adds two `Config` fields, `Embedded` and
`RunID`, and no existing caller has to set either. The caller-`ctx`
lifecycle and the run identity stay 1.1 unless a run sets `Embedded`; the
fixes under "Changes for every format" reach every run. Decision record:
[`docs/decisions/caller-cancellation.md`](../decisions/caller-cancellation.md).

## Changes for every format

These reach every run, whether or not it sets `Embedded`:

- **^C during Finish stops the run.** In 1.1, SIGINT/SIGTERM were acted
  on only until the run callback returned. In the usual shape — declare
  Tasks, return, let Define work run while Finish waits — evo still held
  the signal registration, so a ^C was caught and ignored: the run kept
  going until its work finished. Now it interrupts the run like any other
  ^C: running Tasks are cancelled, queued Tasks are `not_started`, the
  band prints, and the exit code is 130. That holds even when every Task
  had already finished.
- **A run waiting on the state lock stops on ^C.** A run queued behind
  another run's exclusive manifest lock (spec §11.3) now stops at once
  instead of waiting for the other run to finish.
- **A cancelled document names its cause.** A cancelled `FormatJSON`
  document, and the JSONL `run.finished` payload, gain
  `"cancellation": {"cause": "user"}` (or `"caller"` / `"deadline"` for
  an `Embedded` run). Every other document is unchanged. A strict reader
  that rejects unknown keys must accept this one.
- **`FormatJSON` write failures wrap the writer's error.** The error from
  `Finish`/`Close` still matches `ErrRenderer` and now also matches the
  writer's own error under `errors.Is`. Its text names the failed step
  (`evo: renderer failure: evo: write evo.run document: ...`).

## `FormatExternal` hosts from 1.1: the lifecycle does not change

A 1.1 host that renders `Snapshot()` itself keeps the 1.1 lifecycle: evo
still handles ^C for its run, a `ctx` that ends mid-run still fails the
running Define (exit 2), and `run_id` / `Conclusion.RunID` /
`Snapshot().OutputID` are still `out_1`. Only the fixes under "Changes
for every format" reach it. `FormatExternal` chooses how a run renders,
not who owns its lifecycle (DEC-CANCEL-005).

## Opt in: `Config.Embedded` makes the caller's `ctx` the run's lifecycle

Set `Embedded: true` when a host drives the run, such as an HTTP handler
with one Output per request. It works with any `Format`, and it is
honored on the `Config.Options` path too.

```go
out := evo.Init(evo.Config{Isolated: true, Embedded: true, Format: evo.FormatExternal, Stdout: io.Discard, Stderr: io.Discard})
```

Four things change for that run, and only for that run.

**A cancelled `ctx` concludes `cancelled` (130).** Before, the run
concluded `failed`, exit 2, with a `context canceled` (or
`context deadline exceeded`) problem, and queued Tasks still ran. Now
running Tasks are marked cancelled, queued Tasks resolve `not_started`,
and `Conclusion.Explanation` is `by caller` or `deadline exceeded`.
Branch on the state:

```go
result := out.Run(ctx, run)
switch result.Conclusion.State {
case evo.StateCancelled:
	// ctx ended: client gone, deadline passed, or shutdown
case evo.StateFailed:
	// the work itself failed
}
```

`Result.Err` is unchanged: it is still whatever your run callback
returned. A `ctx` that ends after every Task has already finished changes
nothing; the completed run reports its own outcome.

**Tasks do not see the caller's deadline.** A Task's `ctx` carries the
caller's values but reports no deadline and is cancelled only by the
run's interrupt. `ctx.Err()` is `context.Canceled`; use
`context.Cause(ctx)` to tell a passed deadline
(`context.DeadlineExceeded`) from a disconnect. A Task that needs its own
budget sets one with `context.WithTimeout` inside the Define.

**Evo registers no SIGINT/SIGTERM handler.** The host owns process
signals. Stop the run by ending its `ctx`; a host in a terminal installs
its own handler and ends the `ctx` from it.

**`run_id` is random.** Every run otherwise carries `"run_id": "out_1"`,
so concurrent requests would share one. An `Embedded` run's identity is
`run_` plus a random suffix, unique per run: correlate on it, never
compare it to a literal. A golden test pins it with `Config.RunID`, the
way it pins time with `Config.Clock`:

```go
out := evo.Init(evo.Config{Embedded: true, Format: evo.FormatJSON, Clock: testkit.NewClock(), RunID: "run_golden"})
```

Task, Group, and message ids are unchanged (the first Task is still
`task_2`).

## MCP API-062 applies from 1.2 pins

Review reports package-level `evo.Task`/`Group`/`Sequence`/`Fact`/`Warn`/
`Print*`/`Confirm` reached from an Isolated Output's `Run` callback,
including inside the package functions it calls, as API-062.
It fires for the current recommendation and pins at 1.2.0 or later, never
for a 1.0.x or 1.1.x pin.
