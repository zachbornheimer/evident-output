# 2.0 landing and release-gate procedure (handoff)

Dated ruling, never normative. This records how the 2.0 release work on
`feat/contract-2.0` is landed and gated so that any agent can continue it from
the atask board alone (`atask list --project evident-output open`).

## State of the work

- Branch `feat/contract-2.0`, worktree `~/Developer/Personal/.worktrees/evident-output-feat-contract-2.0`,
  draft PR #11 to `main`. The main checkout stays clean.
- Every change is an atask task with one verification item. Workers claim a task
  (`atask claim <id>` from the repo root), work in the worktree atask prints, commit
  with `wt step commit -y` (conventional subject, no trailers), and finish with
  `atask verify complete`. Workers never merge.
- Release chain: `at-73pd6d` (two Opus SHIP reviews) → `at-3v32rf` (merge PR #11 to
  main) → `at-bcd460` (tag v2.0.0 then mcp/v2.0.0; also requires `at-g5f6ca`, the
  idle-host perf check) → productgen adoption on the zyins board (`at-gh203z` …).

## Landing completed tasks

1. One merge at a time. From the TASK worktree (never from the feat worktree):
   `wt merge --no-squash feat/contract-2.0`. Running it from the feat worktree merges
   feat into the target and deletes the feat worktree.
2. If the worktree was pruned, recreate it from the branch: `wt switch atask/<id>`
   from the repo root.
3. Conflicts: modify/delete resolves as deletion wins; a commit whose subject is
   already on feat is skipped (`git rebase --skip`); content conflicts are resolved
   by hand, then `git -C /abs/worktree add <file>` (literal absolute path) and
   `GIT_EDITOR=true git -C /abs/worktree rebase --continue`, then merge again.
   `mcp/docs/*.md` and `mcp/internal/agent/sections/embedded/*.md` must stay
   byte-identical (copy after resolving).
4. Never commit on feat while a merge is running (HEAD lock fails). Under load above
   300 a `wt merge` can time out leaving an open rebase with a staged, uncommitted
   pick: `git commit -C <original sha>` then `rebase --continue`.
5. After every batch: `mise run ci` in a detached tmux session (the harness kills
   long foreground jobs), capturing `echo mise-exit=$?` into the log; a green exit is
   `mise-exit=0`, never the harness's own exit code. Known drift after refactors:
   red-proof patches (`tools/scripts/red-proof/patches/*.patch`, rewrite by hand so the
   entry's tests go red with the patch applied), the MCP surface stub
   (`cd mcp && UPDATE_SURFACE_STUB=1 go test ./internal/agent/review -run TestSurfaceStubIsCurrent`),
   the API golden (`cd mcp && UPDATE_API_GOLDEN=1 go test ./guards -run TestAPIGolden_PublicSurfaceMatchesCommittedGolden`).
6. Push with `wt sync --push-only` from the feat worktree; watch `gh pr checks 11`
   (hosted gate = `mise run ci-hosted`, min-go on Go 1.25, five cross targets).

## Release-gate review round

Two fresh Opus reviewers, read-only against `git archive <tip>` of the feat worktree
plus a scratch `git clone` at the tip for tests needing `.git`, `mise run red-proof`
and the release rehearsal (cut-release in the clone, file:// GOPROXY, `go get` and
`go install` of both modules at v2.0.0, both binaries print v2.0.0). Never tag or
push the real repo. Each writes `REVIEW.md`: first line `verdict: SHIP` or
`verdict: DO NOT SHIP`, then `## Blocking`, `## Non-blocking`, `## Verified`, every
finding with file:line, a reproduction and what correct looks like.

- Reviewer 1 lens: structure, abstraction, contract, MCP. Write the 30-line program
  from CONTRACT.md alone and run it in all four outputs, piped and on a pty; every
  symbol irreducible and unmisreadable; LAYOUT and root-thin; each guard fails on one
  violation; diff every test, guard, golden, schema and waiver change since the last
  reviewed tip and judge each narrowing; MCP teaches only 2.0 and converges on
  `examples/`, the v1.0.0 quickstart and a fresh 1.x program; CHANGELOG, migration
  guide and CONTRACT agree; all gates.
- Reviewer 2 lens: runtime, concurrency, freshness, performance. Pooled-worker
  scheduler under `-race -count=5` and adversarial callbacks (goroutines, Goexit,
  panics, nested Define, Confirm in callbacks, 10k tasks, MaxConcurrency 0 and 1,
  GOMAXPROCS=1, Go 1.25 fallback); the 100 ms promise via
  `tools/verify-quiet-pty-stream.py --tasks 10000 --max-gap-ms 100 --compare-plain`;
  Plain streaming in CI logs; Human final screen equals Plain order on a pty; DAG
  semantics in four modes; the productgen x/o/z/y cascade (changed input regenerates
  downstream, hand-edited output re-runs its producer, dry run writes nothing,
  mtime-only touch runs nothing, same-output conflict fails both and heals, kill -9
  mid-write heals); signals and CleanStop; schemas under a stock draft-2020-12
  validator; `mise run red-proof` all PASS; BenchmarkGroup1kPlain vs v1.0.0.
- The bar (Zach's): 2.0 ships only when both reviewers say the code cannot be made
  better in structure, abstraction or efficiency without a reason to defer, and the
  usage contract is irreducible and impossible to misread. Done means safe (no silent
  stale output, correct outcomes and exit codes, no data loss), useful (productgen's
  cascade holds), usable (pinnable v2.0.0, docs and MCP teach only 2.0).
- Host load is usually high: `nice -n 10`, `go test -timeout 25m -p 2`, record
  `uptime` beside timings; reviewers run concurrently, so never two full `mise run ci`.

## Filing findings

Every finding, blocking and non-blocking, becomes one atask task with exactly one
verification item, gating `at-73pd6d` (`atask update at-73pd6d --requires <id>`).
When a finding needs a contract change, file a contract task first (CONTRACT sentence
plus a red test) and an implementation task that requires it. Proofs are at most 300
characters and run in 30 s; the long suite goes in `--regression` with `size=large`.
Round history: rounds 1–10 all returned DO NOT SHIP; every finding was filed and fixed.
Round 11 starts when every open round-10 task is merged and CI is green on the pushed tip.

## Worker brief (give verbatim to any worker)

Executor mode. `atask claim <id>` from the repo root, `cd` into the printed worktree,
`atask context <id>` for the proof and the finding, red test first, fix,
`wt step commit -y`, `atask log --done … --next …`, `atask verify complete`. Not done
until the engine says complete. Do not merge. Go via `/opt/homebrew/bin/mise exec -- go`
if plain go is not 1.27.2; `nice -n 10`, `go test -p 2`. Sources of truth: CONTRACT.md
(symbol tables parsed by TestContractIsTheWholeSurface and TestContractSignaturesTypeCheck),
LAYOUT.md (TestLayoutIsExact), docs/migration/2.0.md (TestMigrationGuideMapsEveryRemovedName);
`cd mcp && go test ./guards`, `go run ./tools/scripts/spec-score --lint --gate` and
TestRootIsThin (4,000 code lines) must stay green; goldens regenerate only through their
update path, each diff justified in the commit body. Never run `git add/commit/push/stash/
restore/switch/checkout/rebase/worktree` directly; `wt step rebase feat/contract-2.0` on
BASE_CONFLICT; never set HK=0 or HK_SKIP_STEPS; never weaken a guard, golden or test to go
green; a false positive from gosec/ruff/staticcheck means restructure the code; red test and
fix in one commit; `mise run lint` before verifying. BSD sed has no `\b` and `-i` needs `''`.
Proof checks have 30 s; if a proof is wrong for the worktree, fix the code to match the proof,
not the proof, and say so in the final reply if the proof is impossible.

Headless alternative that measured 9 min per small task versus 20–60 min for in-session
agents under load 300: run, inside the claimed worktree in a detached tmux session,
`claude -p --model sonnet --dangerously-skip-permissions --strict-mcp-config
--mcp-config '{"mcpServers":{}}' --setting-sources project --no-session-persistence
--tools Bash,Read,Edit,Write,Grep,Glob --system-prompt "<this worker brief>"
"<atask context output>"`, and record wall time.
