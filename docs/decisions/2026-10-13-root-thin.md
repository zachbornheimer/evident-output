# Decision: Root-thin move map

**Status:** Accepted
**Date:** 2026-10-13
**Tasks:** atask `root-thin-05` … `root-thin-15` (at-maskss, at-2df755,
at-my5xx6, at-p3403c, at-5cmktx, at-maxxdw, at-8xwxpy, at-t45m1p, at-fwypp0,
at-3c51g9, at-cfad40)

## Context

The 2.0 layout (`LAYOUT.md`) promises a root package that holds the public
surface and the composition root, and nothing else. Children 01 to 04 removed
`internal/engine` by folding it into root, file by file. Each folded file left
a `// --- folded from <file>.go ---` marker. Root stood at 9,998 non-test
lines when child 05 began. `TestRootIsThin` (child 15) will hold it under
4,000 lines with no marker.

The plan that set this order was lost with a machine restart. This record
restates it from the atask outcomes and from reading each seam.

## Rulings

### R1: each owner gets its own state type

Go cannot split one type's methods across packages. A seam that moves cannot
take `*Run` or `taskState` with it. Each owner package gets its own state
type, keyed by `record.TaskID` or by the graph node:

- `taskState` splits. Its scheduling half (node, handle, declaration,
  container membership) becomes fields of `graph.Task` and `graph.Container`.
  Its presentation half (filing, census, heartbeat, tail, stream marks)
  becomes project rows.
- project follows record through the existing `record.Listener`. It keeps its
  rows keyed by `record.TaskID`. It never reads root's state.
- freshness keeps its per-Task state in `freshness.Run`. change keeps its
  state in `change.Run`. Retained process evidence is a `record.Evidence`.

### R2: root writes no record

Only graph, freshness and change append to record.

- Task-scoped writes go through `graph.Task`: Doing, Summary, Problem, Fact,
  Progress, warnings and phases.
- Run-scoped writes go through graph's run root node: `Run.Fact`, run
  warnings, Print messages, Debug and slog records, journal events and the
  Conclusion.
- "Which ledger sections were streamed" becomes project state.
- The misuse line is rendered by project from the structured misuse note.
- A change's own record writes (ledger rows, ledger sections, verification
  details) are made by change, which is a producer.

### R3: the change.Host adapter

`change.Host` is the port change's operations call. It stays as it is, so the
change tests keep their fake. Child 05 moves its implementation into
`internal/change` (`change.NewHost`). That implementation is built over
`change.Engine`, a smaller interface the root implements:

| Engine method                                                       | What the root lends                                                                 |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `Lock`, `Unlock`                                                    | begin and end one operation under the run's lock (`o.mu`)                           |
| `LedgerTense(id)`                                                   | reach the Task's ledger target: open, unresolved, in the run's tense; misuse if not |
| `CheckOpen()`                                                       | refuse a write once the run is closing, recording misuse                            |
| `Observe`, `SectionOpened`, `EntryRecorded`, `VerificationRecorded` | announce an operation step or a record write to the reader                          |
| `DryRun`, `FS`, `ShowWaiting`, `Spawn`                              | settings, live activity and the process facade                                      |
| `RecordMisuse`, `NoteManifestWarning`                               | run-scoped misuse and the once-per-run manifest Fact                                |

change makes the record writes itself, under the run's lock: it opens the
ledger section, records the entry with the verb in the section's tense
(`record.LedgerTense.Conjugate`), and attaches verification details. The
manifest calls go to `freshness.Run`, which change may import.

### R4: wire vocabulary stays at the edge

change may not import `internal/project/wire` (its import guard forbids it).
project may not import change. So observation payloads are change-owned Go
values (`change.Observation`, `record.LedgerEntry`,
`record.VerificationDetail`). The root, or project once it owns the stream
(child 11), converts them to `evo.event` lines at the edge. Freshness verdicts
work the same way: `freshness.Run` returns a `TaskCommit` or a
`BasisJudgement`, and the edge narrates it.

### R5: lock order

`o.mu`, then `graph.mu`, then `record.mu`, then leaves. graph imports only
record, misuse and the facades. freshness and change import only record,
graph and the facades. `freshness.TaskTable` and `change.Run` keep their own
leaf mutexes and never call out while holding them.

## Notes from children 05 to 08

- The vocabulary guard (`mcp/guards`, `TestVocabulary_RootFileOwnsConcept`)
  pins which root file declares each exported name: `Exec`, `Effect`,
  `PartialEffect` and the change sentinels stay in `file.go`, and
  `Task.Define` and `Task.Verify` in `run.go`, until child 13 moves them and
  updates the vocabulary with them.
- `graph.MisuseSink` keeps exactly one method (`TestMisuseSinkIsTheGraphsOnlyWayToCallItsCaller`).
  A misuse that must not panic in strict mode goes through the graph's
  contained telling, not a second sink method.
- After child 08, root still calls two record methods that child 14's scan
  may flag: `record.Run.SetListener` (composition wiring in `newOutput`) and
  `record.Run.TakeChanged` (the follower draining the change log). Both are
  reads or wiring, not truth; child 14 decides whether they move or are the
  pinned exceptions.
- The live-index row state (`taskState`, `tasksState`) and the container
  member lookups sit under the `live.go` seam, so child 09 moves them with
  the live engine.

## Notes from child 09

- `live.Board` is live's own state type (R1): a row per Task keyed by
  `record.TaskID` (first paint, followed state, filing, tail) and a node per
  collection keyed by its id (census, child index, verdict counts). It reads
  the run around it through `live.Source` (pull, a Task's view and snapshot,
  a collection's header, whether a root row is in scrollback). Root
  implements `Source` until child 11 moves snapshots into project.
- `live.Engine` paints the board. It takes the run's lock as a
  `sync.Locker` for the animator and the resize watch, and reads the run
  through `live.Scene` (ended, debug pane, resize). It exists only when the
  run has a live surface; its methods are nil-safe.
- `taskState` and `tasksState` stay in root without their live fields: what
  is left is plain, wire and settle bookkeeping, which children 10 and 11
  move. A collection's verdict reads `Board.States`.
- The index audit that every root live test ran is now
  `TestChildIndexFrameEqualsAWalkOfEveryChild` in live, driving a board
  through random transitions.

## Notes from child 10

- `plain.Stream` is the run's human durable text: the one write path every
  library line takes (held while a window is open), the root column, the
  per-Task streaming marks and heartbeats keyed by `record.TaskID`, which
  ledger sections already streamed, whether the debug pane presented a
  record, and Finish's residual. It reads the live region through
  `plain.Region` (the `live.Engine`), the writers through `plain.Sinks`
  (root's facade wiring, `humanSinks`), and a Task's snapshot through
  `plain.Source` until child 11.
- Debug formatting (`FormatHistoryLine`, `WriteDebugPane`,
  `WriteDebugTail`, `DebugPane`) and the child-output line splitter
  (`ChildWriter`) are in `internal/project`. The debug and glyph options
  stay root `Config` wiring, in `run.go`.
- `Residual` returns the primary stream's residual and the live terminal's
  final word from one composition, so the parity test now compares the two
  on an interactive run.

## Notes from child 11

- `project.Rows` is the shared row model: a `DeclaredTask` per Task (keyed
  by `record.TaskID`, its key read live from the graph node so a key
  override after declaration holds) and a `DeclaredGroup` per collection.
  Views, snapshots, collection headers, the collection verdict and the run's
  next steps are built there. It reads the live board and freshness through
  `project.Lens`. `StateCounts` moved from live to project with it.
- `project.Follower` is the `record.Listener`. It pulls the change log and
  asks `project.Reactions` (root's `settleReactions`) what each write owes;
  the journal event a settle owes is still written by root through the
  graph's run root node.
- `wire.Events` is the `evo.event` stream with its own sequence and first
  error; `wire.WriteRun`, `wire.WriteMachine` and `wire.WriteJournalLine`
  write the other machine streams. Root wraps their errors in
  `ErrRenderer`. `wire.Release` replaces root's `publishedRelease`; the
  release tooling (`sync-release-pins`, `cut-release.sh`, `mise doctor`)
  reads it there.
- `record.Run.SettledTasks` is now `CountSettled`: the record-write guard
  read the `Settle` prefix as a write.

## Notes from child 14

- `TestOnlyProducersWriteRecord` and `TestOnlyFacadesTouchTheSystem` scan
  the root package's production files beside `internal/`. The one root
  exception is `os` used for nothing but `os.Signal`
  (`usesOSOnlyForSignal`), pinned by `TestRecordAndSystemGuardsScanRoot`'s
  probes.
- `record.Run.SetListener` is now `Listen`: subscribing is wiring, not
  truth, and the guard read the `Set` prefix as a write. Root no longer
  calls `TakeChanged`; the follower does.

## Notes from child 15

- `present.Presenter` (`internal/project/present`) is the one presenter the
  root holds (`Run.show`). It composes the row model, the live board and
  engine, the durable stream, the evo.event stream and the follower, owns
  the per-Task presentation bookkeeping (started, answered, gates) and the
  snapshot version, and is the run's `record.Listener`. It journals through
  `present.Host`, which root implements over the graph's run root node.
- Print line assembly is `project.PrintLines`, the CleanStop registry is
  `graph.CleanStops`, and the Sequence "one Running child" check is
  `graph.Container.StepStarted`.
- Root comments were cut to the reasons they carry: incident history,
  provenance tags and restatements of the code went, exported docs stayed.
  `TestRootIsThin` holds root under 4,000 non-test lines with no
  folded-from seam; it stood at 3,936 when the guard landed.

## Consequences

- Each child is gated by its own proof (its markers gone) and by
  `TestOnlyFacadesTouchTheSystem`. Every commit keeps the contract, layout,
  lint, api-contract, MCP guard and spec-ratchet gates green.
- Moved code keeps its tests, moved beside it. A test is deleted only with the
  dead symbol it covered.
- The spec ratchet cites tests by package and name, and the regression check
  does not run it. After any child moves or renames a test, run
  `go run ./tools/scripts/spec-score --lint --gate` before
  `atask verify complete`, and re-point the requirement (same `CONTRACT.md`
  quote) in the same commit.
- This record is a ruling, not a contract. `CONTRACT.md` and `LAYOUT.md` stay
  normative.
