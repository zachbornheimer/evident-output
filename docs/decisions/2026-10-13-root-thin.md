# Decision: Root-thin move map

**Status:** Accepted
**Date:** 2026-10-13
**Tasks:** atask `root-thin-05` … `root-thin-15` (at-maskss, at-2df755,
at-my5xx6, at-p3403c, at-5cmktx, at-maxxdw, at-8xwxpy, at-t45m1p, at-fwypp0,
at-3c51g9, at-cfad40)

## Context

The 2.0 layout (`LAYOUT.md`) promises a root package that holds the public
surface and the composition root, and nothing else. Children 01 to 04 removed
`internal/engine` by folding it into root, file by file. Each folded file left
a `// --- folded from <file>.go ---` marker. Root stood at 9,998 non-test
lines when child 05 began. `TestRootIsThin` (child 15) will hold it under
4,000 lines with no marker.

The plan that set this order was lost with a machine restart. This record
restates it from the atask outcomes and from reading each seam.

## Rulings

### R1: each owner gets its own state type

Go cannot split one type's methods across packages. A seam that moves cannot
take `*Run` or `taskState` with it. Each owner package gets its own state
type, keyed by `record.TaskID` or by the graph node:

- `taskState` splits. Its scheduling half (node, handle, declaration,
  container membership) becomes fields of `graph.Task` and `graph.Container`.
  Its presentation half (filing, census, heartbeat, tail, stream marks)
  becomes project rows.
- project follows record through the existing `record.Listener`. It keeps its
  rows keyed by `record.TaskID`. It never reads root's state.
- freshness keeps its per-Task state in `freshness.Run`. change keeps its
  state in `change.Run`. Retained process evidence is a `record.Evidence`.

### R2: root writes no record

Only graph, freshness and change append to record.

- Task-scoped writes go through `graph.Task`: Doing, Summary, Problem, Fact,
  Progress, warnings and phases.
- Run-scoped writes go through graph's run root node: `Run.Fact`, run
  warnings, Print messages, Debug and slog records, journal events and the
  Conclusion.
- "Which ledger sections were streamed" becomes project state.
- The misuse line is rendered by project from the structured misuse note.
- A change's own record writes (ledger rows, ledger sections, verification
  details) are made by change, which is a producer.

### R3: the change.Host adapter

`change.Host` is the port change's operations call. It stays as it is, so the
change tests keep their fake. Child 05 moves its implementation into
`internal/change` (`change.NewHost`). That implementation is built over
`change.Engine`, a smaller interface the root implements:

| Engine method                                                       | What the root lends                                                                 |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `Lock`, `Unlock`                                                    | begin and end one operation under the run's lock (`o.mu`)                           |
| `LedgerTense(id)`                                                   | reach the Task's ledger target: open, unresolved, in the run's tense; misuse if not |
| `CheckOpen()`                                                       | refuse a write once the run is closing, recording misuse                            |
| `Observe`, `SectionOpened`, `EntryRecorded`, `VerificationRecorded` | announce an operation step or a record write to the reader                          |
| `DryRun`, `FS`, `ShowWaiting`, `Spawn`                              | settings, live activity and the process facade                                      |
| `RecordMisuse`, `NoteManifestWarning`                               | run-scoped misuse and the once-per-run manifest Fact                                |

change makes the record writes itself, under the run's lock: it opens the
ledger section, records the entry with the verb in the section's tense
(`record.LedgerTense.Conjugate`), and attaches verification details. The
manifest calls go to `freshness.Run`, which change may import.

### R4: wire vocabulary stays at the edge

change may not import `internal/project/wire` (its import guard forbids it).
project may not import change. So observation payloads are change-owned Go
values (`change.Observation`, `record.LedgerEntry`,
`record.VerificationDetail`). The root, or project once it owns the stream
(child 11), converts them to `evo.event` lines at the edge. Freshness verdicts
work the same way: `freshness.Run` returns a `TaskCommit` or a
`BasisJudgement`, and the edge narrates it.

### R5: lock order

`o.mu`, then `graph.mu`, then `record.mu`, then leaves. graph imports only
record, misuse and the facades. freshness and change import only record,
graph and the facades. `freshness.TaskTable` and `change.Run` keep their own
leaf mutexes and never call out while holding them.

## Consequences

- Each child is gated by its own proof (its markers gone) and by
  `TestOnlyFacadesTouchTheSystem`. Every commit keeps the contract, layout,
  lint, api-contract, MCP guard and spec-ratchet gates green.
- Moved code keeps its tests, moved beside it. A test is deleted only with the
  dead symbol it covered.
- This record is a ruling, not a contract. `CONTRACT.md` and `LAYOUT.md` stay
  normative.
